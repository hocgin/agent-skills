# 设计原则与验收

## 从参考图提取可迁移语言

先观察再解释。每个结论绑定 `reference_id`，并区分 `observed`（实际可见）、`inferred`（推断）、`normalized`（为实现确定的规范值）。不从截图断言字体的精确家族、pt、模糊半径或物理光照参数；将估计值转成统一 token 后保持稳定。

| 维度 | 需要确定的内容 | 转译到 Onboarding |
| --- | --- | --- |
| 视觉风格 | 主风格、次风格、最多三项签名特征 | 选择一套主渲染语言；次风格只控制指定维度 |
| 颜色 | 主/辅助/背景/文字、渐变、透明度、对比 | 建立语义颜色；采样和估计必须区分；阅读区域保持稳定底色 |
| 排版 | 字体类别、字重、层级、对齐、行高 | 真实可排版文字、中文替代字体；海报大标题转为可适配布局 |
| 布局 | 焦点、留白、排列、卡片、空间节奏 | 保留视觉重心规律，重新安排主视觉、文案、导航区域 |
| 图形 | 插画/摄影/3D/物体/装饰 | 保留线条、几何复杂度和材质；主体重新取自产品能力 |
| 细节 | 阴影、描边、圆角、光照、模糊、纹理、层次 | 固化可测量 token 和可描述的渲染边界，限制深度层数 |
| 情绪 | 科技、温暖、活泼、治愈、专业等 | 用色彩、光比、节奏实现，避免仅堆叠形容词 |

签名特征应脱离主体仍可识别，例如“左上漫射光 + 冷蓝玻璃边缘 + 大块偏左留白”。“画一朵云”是内容，不是风格。

多参考图：每张先写证据，再按共同材质、光照、字体和色板分组。无法确定主组时用产品适配度和共同证据选择，记录取舍；只有选择会改变用户明确需求时才询问。主风格支配材质与光照；次风格可影响排版等单一维度，禁止把写实摄影与扁平线描随机分派给不同页面。

非引导页参考：保留海报的留白节奏而非信息密度；保留摄影的光影而非原品牌物品；保留 App 卡片的边缘和层次而非复制整个截图。显式风格覆盖时写出保留、转换、放弃的特征及原因。

## 产品内容与视觉对象

先提炼用户获得的结果，再挑选能解释结果的对象。每页能补全：“用户通过 ___ 功能得到 ___，所以用 ___ 场景表达。”

| 类型 | 可能的对象/场景 | 必须贴近的真实能力 |
| --- | --- | --- |
| 音乐 | 唱片、专辑、音波、歌词随播放演进 | 发现、播放、收藏等实际功能；避免虚构版权曲库或音质 |
| 天气 | 天空、云、雨线、日照在时间上的变化 | 当前天气、逐时预报、提醒；不要把天气当纯装饰 |
| 效率 | 任务归组、时间轴、工作流完成状态 | 计划、执行、回顾中的具体收益 |
| 输入法 | 触键、候选词、光标、短语成句 | 真实输入、纠错或语言能力；不可只展示聊天气泡 |
| AI | 用户输入到结果的可辨认转化 | 实际输入输出；抽象光球只能辅助，不能独占所有页面 |
| 健康 | 生活情境、趋势、记录到反馈 | 记录与习惯支持，避免凭空声称诊断/疗效 |

这些是语义起点，不是预定页数或风格。相同 Profile 用在音乐与天气中，应共享光照、材质、构图语法，同时分别展示听觉内容与自然变化。

默认 3 页即可完成价值到行动。4～5 页必须各有新增价值。每页通常一行短标题（中文约 8～14 字）、一至两句说明（约 20～45 字），这是编辑起点，不是硬性截断规则；本地化或放大文字后允许换行和滚动。避免声称用户尚未授予权限、尚未购买的能力已启用。

## 移动端构图与交互

- 以安全区内可用高度为基准：主视觉约 45～55%，文案约 20～25%，导航约 15～20%，余量留白；随屏幕与字号调整，不应造成重叠。
- 画布尺寸为设计样例；系统安全区动态读取，背景可出血，文字、进度和按钮不能被传感器区域或 Home Indicator 遮挡。
- 小屏和大字号先缩减装饰与主视觉，再让内容滚动，保留可达的 CTA。横屏/较宽比例重组留白，不拉伸资源。
- 共用标题层级、内容宽度、按钮高度、导航区和进度规则；布局在已批准变体间切换。每页一个焦点、一个主要行动。
- 普通正文对比度设计目标至少 4.5:1，大字至少 3:1；透明层需按合成后的实际底色复核。交互区域默认至少 44×44 pt 的设计目标；不依赖颜色传递唯一含义。
- 跳过、继续、返回、滑动与最后 CTA 的目标一致；是否可跳过跟随真实产品需求。说明完成标记、重播入口和权限触发时机。
- 动效围绕视线和功能变化：同一光源、视角与主体锚点；只改变需要解释的信息。避免持续高速旋转、无意义视差和滚动劫持。
- Reduce Motion 保留信息与状态变化，用短淡入或直接切换替代位移/缩放；可中断，快速滑动不导致动画排队。

## 实现与资源边界

代码负责真实文案、按钮、进度、导航、可访问性、基本卡片/图形、渐变及可控阴影。摄影、复杂 3D、细腻纹理或多物体插画可为独立资源。纯主视觉资源不含标题/CTA/状态栏，不把一张整屏图当作可操作 UI。

资源注明每页 asset ID、透明/不透明背景、比例、裁切保护区、导出像素建议与替代方案。像素按**展示 pt × 目标 scale**推导，不能把 393 pt 当成所有设备的像素宽度。资源若自带固定光照，不叠加冲突的运行时光影。

SwiftUI 可采用数据驱动的分页容器、共享 token 和导航组件；由系统布局、安全区和动态字号决定实际尺寸。玻璃效果提供不支持背景模糊时的实色表面回退；具体 API 在实际编码时核对部署目标。这里只提供方向，不声称已编译或运行。

## 七维验收

每项记录 `pass` / `revised` / `blocked`，证据、修正及验证范围。`revised` 表示修正后已重检通过，`blocked` 不得宣称最终通过。

| 项目 | 通过条件 | 失败时先修什么 |
| --- | --- | --- |
| 风格一致性 | 所有页同一 ID/版本、色板、字体、材质、光源；独立提示词含相同锁 | 修 Profile 的歧义或冲突，重编全部页面 |
| 产品相关性 | 每页功能对应产品事实/明确假设，视觉解释该功能 | 改功能映射和主体，删除无关装饰 |
| 构图质量 | 焦点、文字、CTA 分层，安全区/小屏/大字号有适配 | 调整布局变体、比例和裁切 |
| 内容完整性 | 页间提供不同价值，顺序合理，开始/跳过/最后动作明确 | 重排、合并重复页，补全终点 |
| 提示词可执行性 | 独立含对象、位置、材质、色值、文案、交互、转场、禁止项；无矛盾 | 修源字段，避免仅追加风格形容词 |
| 可复用性 | 核心 Profile 无产品专属对象；换项目仍保持设计基因 | 移动产品内容到 Flow；换一种类型口头试译一页 |
| 可实现性 | 各页区分代码/图片，资源有裁切和回退，控件可交互 | 拆解资源，削减不可实现效果，明确状态与降级 |

结构验收和方案语义验收不等于渲染或设备验收。未出图只确认提示词层面的统一约束；未设备验证不写“小屏已通过”。
