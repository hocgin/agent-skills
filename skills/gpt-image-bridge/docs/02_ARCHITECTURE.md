# 架构设计与核心逻辑

```text
调用方 → bin/gpt-image-2 → codex exec → image_generation
             ↓                  ↓
         最终输出路径 ← 复制 ← 私有临时目录中的 PNG
```

1. 解析两个位置参数和可选参数，检查 Codex 可执行文件与输出父目录。
2. 检查所有参考图文件；根据调用方的工作目录将路径绝对化。Git Bash 下若有 `cygpath`，转换为本机可识别的路径。
3. 创建 `gpt-image-2.XXXXXX` 私有临时目录，日志位于相邻的 `.log` 文件中。
4. 调用 `codex exec --skip-git-repo-check -s workspace-write -C <workdir>`。每张参考图以独立的 `--image=<path>` 参数传入，避免多值 `--image` 吞掉提示词。空数组展开保持兼容 macOS Bash 3.2 的 `set -u`。
5. 提示词要求实际调用图片生成工具、参考附件像素并将结果保存为临时目录中的 `out.png`。尺寸以提示词请求传递，没有另外指定模型或 API 请求。
6. 优先取 `out.png`，否则沿用上游行为选择临时目录中最新的 PNG；只有 Codex 成功退出并找到 PNG 后才复制到目标路径。
7. 成功后尽力清理临时文件；失败时保留目录及日志用于诊断。

参考图直接作为附件读取，不复制到临时输出目录。脚本仅检查参考图和输出 PNG 是否存在，不验证图像内容；代理需要读取输出检查结果。目标复制使用普通 `cp`，不是原子替换；磁盘写入失败仍可能影响目标文件。内层 Codex 只处理临时相对输出路径，最终路径由外层脚本处理。
