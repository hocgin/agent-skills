# 从案例图提取风格

用户提供一张或多张 App Icon 案例图，并要求「分析 / 提取 / 保存为风格」时执行。

## 1. 分组

- **一种设计语言 = 一个风格**。逐张观察后判断：
  - 多张图配色、材质、光影、构图骨架一致，只是主体不同 → 合并为**一个**风格，多张图都作为参考图。
  - 设计语言明显不同 → **各自**建立风格，分别命名。
  - 同一张图里混有多种语言、或分组拿不准 → 询问用户。
- 与已有风格高度相似（查看 `styles/index.md`）→ 建议作为已有风格的补充参考图，并询问用户。

## 2. 七维提取

只提取**所有案例共有**的特征；单张独有的内容归入「可变元素」。

| 维度 | 需要回答的问题 |
|---|---|
| 配色 | 几种颜色？各自角色（底色 / 主体 / 焦点 / 装饰 / 强调）？估算 HEX（可用脚本取色，见下） |
| 造型 | 主体是实物、角色、抽象符号还是字母？几何还是有机？圆角大小？比例？ |
| 材质 | 扁平 / 拟物塑料 / 金属 / 玻璃 / 黏土 / 纸张 / 毛绒？有无磨砂、光泽？ |
| 光影 | 光源方向？柔光 / 硬光？有无高光、AO、投影、内发光？ |
| 构图 | 主体是**铺满画布**还是**底板上的物体**？视角（正视 / 俯视 / 等距）？焦点位置？装饰元素位置？ |
| 质感 | 颗粒、噪点、印刷网点、做旧、划痕、渐变平滑度 |
| 细节 | 装饰元素的形态与数量上限；文字 / 数字的出现方式；细节密度 |

再总结：**签名特征**（1–3 个，去掉它就不是这个风格）、情绪关键词（3–4 个）、适合的项目类型、**主体转译规则**（任意项目的隐喻如何变成该风格下的主体）。

取色辅助（需要 Pillow）：

```bash
python3 -c "from PIL import Image; im=Image.open('<图片>').convert('RGB'); print(['#%02X%02X%02X'%im.getpixel(p) for p in [(x,y),...]])"
```

## 3. 命名

- `id`：小写短横线，2 个词以内，描述**风格**而非内容，如 `retro-stripe`、`clay-pastel`、`glass-gradient`。
- `name`：4 字以内中文名。
- 不与已有风格重名。

## 4. 创建文件

```bash
python3 scripts/build_prompt.py --new <id> --name <中文名> --ref <图片1> [--ref <图片2> ...]
```

脚本会创建 `styles/<id>/`，复制参考图为 `reference.png`、`reference-2.png`…，并由 `_template.md` 生成 `style.md`。然后按模板填写：

- `style` 块：英文、只写「怎么画」，不提任何具体主体；覆盖渲染方式、配色角色与 HEX、材质、光影、质感、装饰元素、细节密度。
- `composition` 块：英文，描述视角、主体与画布关系（铺满 / 底板）、焦点位置、装饰位置。
- `negative` 块：英文逗号分隔；风格专属禁忌（色板外颜色、违背签名特征的东西）。通用 iOS 禁忌由脚本自动追加，不必重复。
- `label_style`：风格允许出现品牌字样时，写明字样的字体与配色；不允许则留空。
- `keywords`：中英文，供 `--auto` 匹配。

## 5. 注册

1. 在 `styles/index.md` 表格新增一行，并在「自动匹配规则」中补充对应调性。
2. `python3 scripts/build_prompt.py --catalog` 更新 README.md。

## 6. 自检

```bash
python3 scripts/build_prompt.py --list
python3 scripts/build_prompt.py --style <id> --subject "<用案例图原本的主体写的描述>"
```

- 脚本能解析出 style / composition / negative 块；
- 提示词能「复现」案例图（如有生图工具，试生成一张并对照验收清单调整措辞——这是唯一允许修改 style 块的时机）；
- 再用一个**完全不同类型**的项目试写一次主体，确认主体转译规则可用。
