# 从案例图提取风格模板

用户提供一张或多张 App Icon 案例图，并要求「分析 / 提取 / 保存为风格」时执行。

> 目标是沉淀**可复用的设计语言**，而不是保存一张图的「复刻配方」。每张案例图都要拆成两部分：
>
> | 设计 DNA（写进 style / composition） | 参考 IP（写进「参考 IP 排除」/ avoid / ip_terms） |
> |---|---|
> | 渲染方式、材质、光影、质感 | 原主体 / 物件 / 角色 |
> | 配色**角色**与色值 | 标志性轮廓与部件组合 |
> | 造型语言（圆角、线宽、比例夸张方式） | 原布局（各元素的具体位置） |
> | 装饰手法与数量上限 | 文字、字样、品牌名 |
> | 情绪 | 「某主色 + 某物件」这类可识别组合 |

## 1. 分组

- **一种设计语言 = 一个风格**。逐张观察后判断：
  - 多张图配色、材质、光影一致，只是主体不同 → 合并为**一个**风格，多张图都作为参考图（多张图更容易分清 DNA 与 IP）。
  - 设计语言明显不同 → **各自**建立风格，分别命名。
  - 同一张图里混有多种语言、或分组拿不准 → 询问用户。
- 与已有风格高度相似（查看 `styles/index.md`）→ 建议作为已有风格的补充参考图，并询问用户。

## 2. 七维提取（只提 DNA）

只提取**能迁移到任意项目**的特征；单张独有的内容一律归入「参考 IP」或「可变元素」。

| 维度 | 需要回答的问题 |
|---|---|
| 配色 | 几种颜色？各自**角色**（底色 / 主体 / 焦点 / 点缀）？估算 HEX；哪些颜色可按项目替换？ |
| 造型语言 | 几何还是有机？圆角大小？线宽？比例如何夸张？（不写具体物件） |
| 材质 | 扁平 / 拟物塑料 / 金属 / 玻璃 / 黏土 / 纸张 / 毛绒？有无磨砂、光泽？ |
| 光影 | 光源方向？柔光 / 硬光？有无高光、AO、投影、内发光？ |
| 构图原则 | 主体**铺满画布**还是**底板上的物体**？视角？主体占比？焦点数量？（具体位置放到版式变体） |
| 质感 | 颗粒、噪点、印刷网点、做旧、划痕、渐变平滑度 |
| 细节密度 | 装饰元素的形态与数量上限；文字出现方式 |

再总结：**签名手法**（1–3 个，必须是「手法」而不是「物件」——例如「物体正面即背景」可以，「大镜头」不可以）、情绪关键词、适合的项目类型、**主体转译规则**。

取色辅助（需要 Pillow）：

```bash
python3 -c "from PIL import Image; im=Image.open('<图片>').convert('RGB'); print(['#%02X%02X%02X'%im.getpixel(p) for p in [(x,y),...]])"
```

## 3. 列出参考 IP

逐项写出参考图的：原主体 / 角色、标志性部件、原布局、文字 / 品牌。然后：

- 写入 `style.md` 的「参考 IP 排除」章节（中文说明）；
- 转成英文写入 ```avoid``` 块（脚本自动并入 negative）；
- 提炼 3–10 个关键名词写入 front-matter `ip_terms`（主体描述命中即告警）；字母标风格把原字样写入 `ip_labels`。

## 4. 设计版式变体

从参考图的构图**抽象出原则**，再设计 2–4 个 ```composition:<name>``` 版式：

- 版式之间焦点位置、主体占比、视角或装饰走向至少有一项不同；
- **不得有任何一个版式与参考图布局一一对应**（参考布局写进 avoid）；
- 第一个版式为默认版式，应是最通用、最不像参考图的那个；
- 版式只写位置与比例，不写主体是什么。

## 5. 命名

- `id`：小写短横线，2 个词以内，描述**风格**而非内容，如 `retro-stripe`、`clay-pastel`、`glass-gradient`。
- `name`：4 字以内中文名。
- 不与已有风格重名。

## 6. 创建文件

```bash
python3 scripts/build_prompt.py --new <id> --name <中文名> --ref <图片1> [--ref <图片2> ...]
```

脚本会创建 `styles/<id>/`，复制参考图，并由 `_template.md` 生成 `style.md`。按模板填写：

- `style` 块：英文、只写「怎么画」；**禁止出现参考图的主体、角色或具体部件名**（例如不能写 lens、tonearm、star）。
- `composition:<name>` 块：见第 4 步。
- `negative` 块：违背设计 DNA 的禁忌；通用 iOS 禁忌与原创性禁忌由脚本追加。
- `avoid` 块、`ip_terms`、`ip_labels`：见第 3 步。
- `summary`：一句话概括设计语言，不提参考主体。

## 7. 注册

1. 在 `styles/index.md` 表格新增一行，并在「自动匹配规则」中补充对应调性。
2. `python3 scripts/build_prompt.py --catalog` 更新 README.md。

## 8. 自检（迁移性测试）

```bash
python3 scripts/build_prompt.py --list
python3 scripts/build_prompt.py --layouts <id>
```

- 用**两个与参考图类型完全不同**的项目各写一次主体，分别用不同版式拼装；
- 检查 style 块里没有参考主体的名词；对参考主体本身拼装一次，应触发 `WARNING`（说明 ip_terms 生效）；
- 如有生图工具，**不附带参考图**各生成一张，与参考图并排对比：渲染语言应一致，主体 / 轮廓 / 布局应明显不同。风格还原不足时只调整 style 块措辞（这是唯一允许修改 style 块的时机）。
