# iOS Widget 设计评审与评分

本参考将 Wholiver 的 [5-Dimension SwiftUI Design Review](https://raw.githubusercontent.com/Wholiver/swiftui-design-skill/refs/heads/main/references/design-review.md) 评分骨架改写为 WidgetKit 小组件专用框架。它保留五维、每维 1–10 分、低分必须修复的工作方式；凡与 Apple 小组件规范冲突之处，以 [Apple Widgets HIG](https://developer.apple.com/design/human-interface-guidelines/widgets) 和本 Skill 的 HIG 决策指南为准。

适用于主屏幕、Today View、锁定屏幕和 StandBy 的截图、视觉稿、规格说明或 SwiftUI 小组件实现。评审前先确认 WidgetKit 家族、设备屏幕尺寸、iPad 的 Canvas/Device 目标（如适用），以及要验证的渲染模式。

## 评审能力

使用本框架时，能够：

- 从截图、设计稿或 SwiftUI 代码识别小组件的家族、情境、主信息、交互和数据状态；
- 基于实际尺寸与 full-color、accented、vibrant 等适用呈现方式进行五维评分；
- 将评分落实到可观察证据、具体问题和可执行修复，而不是给出笼统审美判断；
- 对修复后的版本重新评分，并说明分数变化的原因；
- 标记因缺少设备、模式、状态或数据而无法确定的项目，避免给出虚假的确定性。

## 评分方法

每个维度独立评分 1–10 分，并为每一分提供一句证据。平均分只用于概览，不能掩盖单项风险。

| 分数 | 含义 | 处理方式 |
| --- | --- | --- |
| 1–3 | 根本不适配小组件或系统情境 | 重新设计该维度，而非微调 |
| 4–5 | 可用但泛化、脆弱或有明显摩擦 | 明确列为交付前改进项 |
| 6–7 | 专业且基本可靠，仍有可见改进空间 | 修复影响理解、适配或效率的问题 |
| 8–10 | 明确、精致、经过情境验证，达到可交付品质 | 记录可复用的成功做法 |

交付门槛：所有维度都至少为 7 分，且没有任何维度低于 5 分。低于 7 分的每一项都需要关联一个具体修复；缺少关键验证素材时，以“暂定分数 + 待验证项”代替通过结论。

## 五个评分维度

### 1. 目的与平台契合度

评估小组件是否有一个明确、及时且可一瞥理解的目的，并像系统的一部分，而不是被压缩的 App 页面。

| 分数 | 标准 |
| --- | --- |
| 1–3 | 主要是 Logo、启动入口或迷你 App；与所处情境无关；忽略系统渲染限制 |
| 4–5 | 内容有价值但目的泛化；尺寸或情境的选择缺乏理由 |
| 6–7 | 主目的明确，所选家族能服务该目的，并大体遵循 HIG |
| 8–10 | 用户在该情境中的问题被立即回答；每个家族和呈现方式都有恰当、原生的理由 |

检查：

- [ ] 能用一句话说清用户打开系统时最想知道或完成什么。
- [ ] 每个支持的家族都提供额外价值，而非仅放大相同内容。
- [ ] 小组件不承诺 WidgetKit 无法提供的实时更新。
- [ ] 对 full-color、accented、vibrant 的适配是有意设计，而非偶然可用。

### 2. 一瞥层级

评估用户能否在短暂注视、最小家族或远距离 StandBy 中先读到正确的信息。

| 分数 | 标准 |
| --- | --- |
| 1–3 | 所有元素权重相近、信息拥挤，或没有清晰的第一阅读点 |
| 4–5 | 有初步层级，但文字、图表、装饰或操作之间仍在竞争 |
| 6–7 | 主、次、辅助信息层级清楚，密度适合该家族 |
| 8–10 | 第一眼即理解，视线自然流动；在缩放、单色和远观情境下仍无竞争元素 |

检查：

- [ ] 主信息是最先被读到的内容，且与小组件目的直接相关。
- [ ] 次要信息支持主结论，不抢占对比度、面积或字号。
- [ ] 空白、分组和图形帮助阅读，没有为了“填满”空间而增加噪声。
- [ ] 小尺寸和 StandBy 不依赖细小正文、密集表格或复杂图例。

### 3. 工艺与自适应呈现

评估细节是否经过系统情境检验，而非只在一张理想截图中看起来整齐。

| 分数 | 标准 |
| --- | --- |
| 1–3 | 间距、对齐、字体、图标或圆角随意；在着色、去色或缩放后失效 |
| 4–5 | 常规全彩状态尚可，但存在可见的不一致或未验证的模式 |
| 6–7 | 使用一致的系统容器、文字、符号和间距；适用模式下清晰可读 |
| 8–10 | 每个细节都有目的，并在尺寸、Dynamic Type、外观和渲染模式间维持稳定层级 |

检查：

- [ ] 标注准确使用目标设备 pt，iPad 还标明 Canvas 或 Device。
- [ ] 默认使用系统边距（通常 16 pt；紧凑分组可为 11 pt），而非任意网格或硬编码 frame。
- [ ] 文字是真实文本、一般不小于 11 pt；字体、SF Symbols 和圆角与系统容器协调。
- [ ] clear、tinted、vibrant、Always-On 和 StandBy（如适用）下对比度与语义仍成立。
- [ ] 所有图标、数字、图像和文字的基线、比例与视觉权重一致。

### 4. 直接效用与状态处理

评估小组件是否以最少摩擦让人获得信息或完成简单、相关的动作。

| 分数 | 标准 |
| --- | --- |
| 1–3 | 关键内容不可用、互动无关或错误，缺少基本状态处理 |
| 4–5 | 能使用，但打开 App 后仍需寻找目标，或加载/空/错误状态不明确 |
| 6–7 | 内容可靠，深链正确；相关互动和主要数据状态均已处理 |
| 8–10 | 在不把小组件变成迷你 App 的前提下，预判用户情境并消除不必要步骤 |

检查：

- [ ] 非交互区域深链到与当前内容相符的详情或行动，而不是 App 首页。
- [ ] 按钮、开关和链接数量有限、目标明确且适合所在家族；inline accessory 只有一个点击目标。
- [ ] 加载、空、错误、过期和登录状态不会呈现空白或误导性内容。
- [ ] Gallery 预览、占位符和描述准确表达该小组件的真实能力。

### 5. 产品特征与原生辨识度

评估小组件是否提供独特的产品价值和恰当的个性，同时仍保持 Apple 平台感。此维度不奖励为了显得“原创”而加入的自定义字体、渐变、颜色或不对称布局。

| 分数 | 标准 |
| --- | --- |
| 1–3 | 模板化、装饰与数据无关，或品牌元素压过信息 |
| 4–5 | 专业但泛化，几乎可属于任何 App |
| 6–7 | 通过特定内容、数据表达或克制的品牌线索体现产品特点 |
| 8–10 | 令人记住的洞见、个性化或数据叙事与任务紧密相连；即使单色或去背景后仍可辨识和有用 |

检查：

- [ ] 至少有一个与产品价值相关的独特信息表达或个性化细节。
- [ ] 品牌色、图形和字体支持而非取代信息；App 图标或 Logo 不是主内容。
- [ ] 没有模板感的伪精致、无意义装饰、流行元素拼贴或虚假的数据图表。
- [ ] 系统字体和系统色在此维度中可以获得高分，只要信息表达具有产品特征。

## 适配边界

- 不把原始框架中的“8pt 网格”“44 × 44 pt 触控目标”“自定义字体/强烈调色才有个性”等通用 App 页面准则直接用于小组件；它们会与 Apple 的系统边距、锁屏 accessory 空间和系统字体建议冲突。
- 若缺少截图、模拟器结果或 SwiftUI 代码，仍可评审概念和规格，但必须将渲染、对比度、Dynamic Type 或交互结论标记为待验证。
- 发现 HIG 违例、错误尺寸、不可读文本、错误深链或误导性实时承诺时，优先将其列为修复问题，即使视觉平均分较高。
